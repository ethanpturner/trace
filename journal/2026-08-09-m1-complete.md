## The pattern held, and the corpus kept losing

The first half found four gaps by writing code. The second half found more, and they were the same
shape: places where a document was internally consistent and disagreed with a decision recorded
after it.

- **`checkpoint_reference`** was in #57's field list. DEC-016 removed the framework it pointed at
  and DEC-017 removed the field.
- **`typer` was "present only transitively"** in #35's body. DEC-016 removed the packages carrying
  it, so adopting it would have been adding a dependency rather than using one.
- **`trust_level` should "default to `untrusted`"** in #52. Section 7 marks it required, and the
  conformance guard from #45 rejected the default on the first run.
- **DX-13, DX-06, DX-17** were all cited as open. All three are recorded decisions.

None of these is a real problem, and that is the point. The backlog was seeded on 2026-08-08 and
sixteen decisions were recorded on 2026-08-09; issue text is a snapshot and the decision log is the
authority. What made it safe was having a guard that reads the document rather than trusting the
issue.

## Four decisions, three of them forced by implementation

**DEC-031** (`Assessment.status`) came from being asked to justify a table I had invented in #50. It
was wrong, and the useful part was *why*: `pending_review` there meant "at a checkpoint", which is
ambiguous between the two checkpoints and duplicates `WorkflowRun.status == paused`. Duplication was
the real defect — a stored status that can disagree with the runs it summarizes is a second
authoritative answer, which DEC-016 rejected in a framework checkpointer and DEC-028 in a declared
count. Three decisions now refuse the same shape, which is a sign it is a real principle rather than
three preferences.

It also answered DEC-012's first open question as a consequence rather than separately: the
non-authoritative marking lives on the run, and the assessment's inability to reach `approved` is
the effect that matters.

**DEC-032** (the interface) was easier than the issue framed it, because DEC-017 had already
answered one of its own decision criteria. Review does not need an interactive interface: a
checkpoint pauses by persisting and exiting, and decisions reach the workflow through one writer
regardless of caller. Three further arguments were already in the corpus and had not been read
together — evaluation wants a scriptable interface, section 5.1 names the CLI as its own recovery
path, and choosing the CLI *removes* a trust boundary rather than mitigating one.

**DEC-033** (`IngestionStatus`) filled a field section 7 requires and enumerates nowhere. Three
values, and the argument worth keeping is the one for *not* adding a fourth: a status the code never
writes is worse than absent, because someone eventually branches on it.

**The threat model** was better written now than when it was scheduled. Its central requirement is
that every mitigation names where it is enforced — and when the backlog was seeded that column would
have been empty. Four of five boundaries now have code to point at. It also produced a status value
I had not planned, `Partial`, because writing it found gitleaks running in pre-commit and not in CI.

## What the tests found that I did not

Three of the more interesting bugs this half came from tests failing, not from reading.

**`str_strip_whitespace` silently violated DEC-015.** `DomainModel` strips whitespace from every
string field, which is right for extracted text and wrong for `quoted_text`: DEC-015 makes it the
verbatim excerpt, DEC-019 hashes it, and the indexer records the line range it came from. Stripping
left the stored text disagreeing with *both its own hash and its own line numbers*. It surfaced as
three failing tests in #55 that looked like a data problem, and the cause was a base-class setting
three files away. Disabling stripping for that field also required replacing `min_length` with an
explicit validator — the two changes have to happen together, which is exactly the kind of coupling
that gets missed.

**My indifference test had a hole.** #54 asserts the loader treats the injection fixture like any
other file, comparing the produced object field by field. The first version excluded `metadata`
wholesale, and a probe that added `suspicious: True` when a line contained `OVERRIDE` slipped past it
entirely — caught only by a separate test that happened to hardcode the expected keys. Metadata
values differ by size and metadata keys must not; the keys are now compared directly.

**A same-length edit produced a false pass.** Verifying guards by editing a file and restoring it
from a backup broke in #55: the probe (`count > 0`) and the original (`count > 1`) are the same byte
length, the restore landed in the same mtime second, and Python reused the cached bytecode. Four
tests appeared to pass against code that was no longer there. I noticed because the numbers looked
wrong, not because anything failed. `__pycache__` now gets cleared between probe and restore, and I
cannot fully rule out that an earlier same-length probe passed falsely.

## Two things I got wrong

**I asserted `Decimal("5.10") != Decimal("5.1")`.** They compare equal. The test was trying to show
the cost field does not route through `float` and was showing nothing.

**I committed a failing test.** #58's README rewrite replaced the explicit command list with a
compact form, and the DEC-032 guard — which requires README and the roadmap to state the same
surface — failed. I caught it on the next command and amended, but the commit existed with a red
suite. The guard did its job; the sequencing did not.

## Where it strains

`quoted_text` now carries a per-field exception to a base-class rule. It is documented in three
places and pinned by tests, and it is still an exception, and the next field that needs one will be
easier to add than to think about.

The `approved` gate depends on `run_is_authoritative` being passed in, because `WorkflowRun` did not
exist when DEC-031 was written and now does. That argument should become a lookup.

Instrumentation is optional on both deterministic nodes, so a caller can forget the ledger. Nothing
guarantees a run exists until there is an orchestrator, and that is M2.
