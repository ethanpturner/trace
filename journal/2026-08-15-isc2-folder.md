# The ISC2 presentation folder: the deck meets the repository

## What changed

`docs/presentation/` now exists (#356): `deck.md`, the repository's authoritative copy of the
talk's 32 slides and speaker notes; `traceability.md`, every checkable slide claim mapped to the
committed artifact or measured number behind it; `handout.md`, the one-page takeaway; and a
README inventorying the assets the presentation consumes — the demo script and recovery plan, the
CI-rendered recording, the hash-pinned report, the scorecard, and the architecture image — by
reference rather than duplication.

## How the draft met the repository

The draft deck was read slide by slide from the author's slide editor, notes included, and
checked against the corpus. Most of the talk is conceptual — an argument about agent security
that makes no claim on this repository — and the traceability file says so explicitly per slide,
because classifying "20 plausible findings" as rhetoric is itself part of holding the acceptance
criterion. The Trace segment needed three corrections, all applied in `deck.md`:

- Slide 22's demo placeholders (SYSTEM / QUESTION / FINDING, literally "[fill in]") resolved to
  ForgeFlow, the evidence question, and fnd-003 — the finding the model proposed and the reviewer
  rejected, which is the DEC-009 thesis on stage.
- Slide 23's demo timing said 6–8 minutes; the committed walkthrough measures about 8:30 with the
  closer, so the deck now says 7–9 and names what to cut.
- Slide 23's "have a backup available" became the demo script's named recovery artifacts.

The deck quotes no measured number in its Trace segment as drafted. Rather than pushing numbers
onto slides, `traceability.md` carries the table of measured numbers available to the segment —
each from `docs/eval/comparison.md`, `docs/eval/ablation.md`, or the demo script — so any number
added later has exactly one permitted source.

## Decisions

- Screenshots stay derived, not committed: CI re-renders the demo GIF when the command surface
  changes, so committed stills would drift; the folder documents the ffmpeg derivation instead,
  which is the demo script's own position.
- The exported slide binary stays out of the repository; `deck.md` is the versioned content and
  the export is regenerated from it. Same reasoning as the deleted `.docx` originals.
