# M6 closes: the pipeline the corpus described finally runs

Six issues, six merges — #301 through #306 — and the gap the milestone existed for is gone:
before today the `Orchestrator` had never been instantiated outside a test, no command drove an
assessment past checkpoint 1, and the fourteen-phase pipeline existed as nodes, a table, and a
promise. It now runs end to end from the command line, offline or live, and the fastest claim in
the repository is one command that replays the whole thing against a pinned hash.

## The orchestrator did not support its own table

The design work hiding inside "wire it up" (#260): `NODES_BY_PHASE` declares two nodes for six
phases, and `register` refused a second node per phase — with a test pinning the refusal, argued
from registration order. The argument was right and aimed at the wrong target: the table is the
order, so multi-node phases keep the property the old test defended while making the table true.
A declared node left unregistered now stops the run, because half a phase is a skipped node
wearing a completed phase's clothes.

Two subtler things fell out. `advance()` replaces list fields, so per-threat loops accumulate
`state_changes` in the adapter before they reach the state, and a new `absorb()` applies results
between the nodes of one phase. And the agent nodes record their own executions — `counters()`
counts model calls by record, so the orchestrator wrapping them again would have doubled every
call against both the audit and the ceiling. `records_own_execution` says who accounts; the
end-to-end test pins one record per execution.

## DEC-031 had a requirement nobody had implemented

`conclude_finding_review` demands `pending_review`, and nothing ever called `begin_review` — the
decision's same-transaction language ("written in the same transaction that sets
`WorkflowRun.status` to paused") had no implementation anywhere, which surfaced only when #261
made checkpoint 2 drivable. The orchestrator gained an `on_pause` callback that runs inside the
pause transaction; the driver supplies `begin_review` through it; resuming returns a
`pending_review` assessment to `draft` before continuing. A failed run leaves `draft` by never
reaching the pause transaction, which is the decision's sentence implemented rather than
paraphrased.

## Recordings say their own type

`--response` became repeatable, and the schema question answered itself: every proposal is
`extra="forbid"`, so the six response schemas are mutually exclusive by construction and a
recording's shape says which call it answers. Exact-match inference, with a refusal for the
empty recording that validates against several — a recording that empty cannot say what it is,
and replaying it would be a guess wearing a recording's clothes.

## Byte-stable means finding the one timestamp

The replay fixture (#263) turned up exactly one source of nondeterminism: the rendered report
carries a single generation timestamp. `generated_at` now flows through the driver to
`publish_report`, the replayer pins it, and two replays are byte-identical — asserted by
replaying twice in the default suite. The recordings themselves are authored offline against the
deterministic model and the provenance note says so plainly; they are shaped exactly as
recordings are consumed, so a live capture replaces them file for file. Claiming more would have
been the kind of quiet overstatement the register rules exist to prevent.

## The demo is a derivative, and it proves itself

The tape (#265) renders the README's recording from the same commands the README documents, and
the workflow that re-renders it fails unless the tape's hidden `trace verify` epilogue wrote its
success marker — VHS itself does not fail when a command inside the terminal fails, so the smoke
came from making the last command's success observable. One mundane fight: the rendered GIF was
1.4 MB against a 500 KB large-file gate, and the answer was gifsicle with the regeneration
commands recorded in the tape header, not a raised limit.

## Open next

M6 is empty. M7 Evaluation opens with the harness (#266, against DEC-073), and the first thing
the harness will want is exactly what M6 built: `run_assessment` and `resume_assessment` as the
ordinary pipeline it is required to call rather than re-implement. The README's
what-does-not-exist list is now the M7–M9 worklist, which is what that section is for.
