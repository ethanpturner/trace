# M0 closes: twenty-one decisions in six clusters

The session took the M0 Decisions milestone from twenty-one open issues to zero. Every issue
closed with its own decision-log entry — DEC-057 through DEC-077 — delivered as six thematic
pull requests (#294 through #299), each cluster merged before the next branched because they
all append to the same file. The clustering followed the issues' own cross-references: #240
asked to land with #228 and #229, #239 paired itself with #227, and the five evaluation issues
form one machine.

## What was decided, in one line each

- **Catalog (DEC-057..059)**: versions are minor-or-major with no patch level — the content
  hash already made in-place patching impossible, and the semantics ratify what the hash
  enforces; released directories freeze at PR time; AISVS and the AI Exchange join 0.2's
  provenance with binding register caveats; cloud-operations becomes a 0.2 category with the
  CC BY 4.0 posture stated beside the share-alike rule.
- **Checkpoints (DEC-060..062)**: the reviewer may assign a risk treatment but is never forced
  to — severity blocks approval, treatment does not, because a forced treatment is a
  fabricated business decision; revisit is episodic with the one authored date on accepted
  risk; routing reasons are derived at package-build time because their inputs are already
  persisted, so derivation *is* the audit.
- **Pipeline (DEC-063..065)**: the STRIDE applicability table enters as warn-only data with
  the checklist pressure answered structurally (a coverage gap is not an error class, so
  nothing can retry against it); reviewer dismissals feed the critic as marked context,
  rationale-bearing only; uncovered concerns become catalog-gap candidates that no report
  section can render.
- **Data model and runtime (DEC-066..069)**: the finding fingerprint is DEC-056's matching
  rule promoted to an object property; cache tokens become their own disjoint spans priced by
  the profile; the five context extensions land as one pass with the trust-zone object
  rejected; model profiles may carry a per-agent overlay refused at load.
- **Ingestion, report, interop (DEC-070..072)**: parsed machine-readable artifacts are
  documented evidence but determinism earns no checkpoint bypass; the coverage ledger lands in
  the methodology section with a renderer that refuses an unaccounted document; exports are a
  serializer family distinct from report formats, ordered TM-BOM, SARIF, Mermaid, with the
  SARIF severity trap closed at decision time.
- **Evaluation (DEC-073..077)**: the harness is a caller of the real pipeline so it cannot
  drift from what it measures; baselines get schema-forced output and input ties resolved
  against Trace; adversarial evaluation is a condition axis with a named compliance-rate
  metric; the scorecard is metrics-only, which is also what keeps attack payloads off a public
  page; stability is measured and gates nothing, because a gated variance number stops being
  honest.

## Reasoning worth keeping

Three recurring moves shaped most entries. First, several issues posed either/or questions the
corpus had already dissolved: #234's "derived and cheap or recorded and auditable" was a false
choice because every reason code derives from persisted fields, and #232's "which section owns
coverage" mattered less than the rule that the renderer must refuse a ledger that does not
account for every document. Second, the DEC-030 pattern — a judgment the documents cannot
answer belongs to the human, and the schema must make the degenerate path unrepresentable —
generalized cleanly to treatment (`accept` without rationale is refused) and to the coverage
baseline (a gap is not an error class). Third, wherever a survey mechanism came from a running
service (ThreatAtlas expiry, appsec-agent's distilled guidance), the decision had to re-derive
it for an episodic, checkpointed system rather than transplant it; the transplants that
survived are the ones that became data or derivation rather than daemon or authority.

Field tables in `data-model.md` were deliberately not touched: the conformance test enforces
table-code agreement in both directions, so every decided field is recorded in section prose
and lands with its implementing change. One mechanical catch: the section 4.4 enum parser
reads bare value lines, so DEC-070's `structured_input` note had to sit below the list rather
than inline — caught by running the suite before pushing.
