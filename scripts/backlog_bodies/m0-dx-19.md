## Context

`ConfidenceLevel` is `low | medium | high` with an optional `confidence_score` decimal
(`docs/architecture/data-model.md` sections 4.2 and 10). `docs/product/design-principles.md`
section 15 warns that a numeric score "can appear scientific while representing little more
than model intuition" and requires evidence strength to be separated from model confidence.
`data-model.md` open question 7 asks whether confidence should be numeric or only
categorical.

Every proposed object carries confidence, so the answer shapes seven schemas. There is a
related loose end: `EvidenceStrength` (section 4.3) is defined and no field on any object
carries it — either a field is missing or the type is vestigial.

`agent-design.md` section 8 also requires the Context Validation node to "enforce confidence
ranges" without saying what consistency between the two representations means.

## Scope

### Options

1. **Categorical only; drop `confidence_score` from version 0.1.** Aligns with design
   principle 15. Removes a documented field, so it is a data-model change.
2. **Categorical, with the score optional and never used for thresholds.** Keeps the field
   and invites the misuse the principle warns about.
3. **Categorical from the model, with evidence strength computed deterministically** from
   `EvidenceStrength` and the evidence hierarchy in `agent-design.md` section 14. Separates
   the two things principle 15 says must be separate, and moves any threshold out of the
   prompt into code, per principle 7.

### Decision criteria

- Does the value change a reviewer's decision, or only make output look precise?
- Are any thresholds enforced on it? If so, design principle 7 puts that enforcement in
  deterministic code and requires the input to be reproducible.
- What does "enforce confidence ranges" mean if both representations are present?
- Does `EvidenceStrength` acquire a field, or is it removed as vestigial?
