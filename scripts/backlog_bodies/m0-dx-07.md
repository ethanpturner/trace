## Context

DEC-005 makes two checkpoints structural, and its own open questions include "what
information should be displayed at each checkpoint." `current-architecture.md` section 11
requires a human-review timeout to pause the workflow, preserve state, and resume when the
reviewer responds — meaning the process may exit and be restarted. This is a local
single-user application (DEC-004), so the process will not be running while the reviewer
reads.

No mechanism exists. `data-model.md` section 31's `pending_human_review` block is
illustrative YAML rather than a schema, and `WorkflowRun.checkpoint_reference` is a free
string with no defined meaning. This is the property most likely to be quietly weakened
into a blocking interactive prompt, which would make the checkpoint unscriptable and force
evaluation runs to bypass it — which is exactly how a structural property becomes optional.

## Scope

### Options

1. **Blocking interactive prompt in one process.** Simplest; cannot survive process exit;
   unscriptable.
2. **Run to checkpoint, persist a paused `WorkflowRun`, exit.** A second command emits a
   review package; a third records decisions and resumes. Survives restart, is scriptable,
   and makes the checkpoint visible in the data.
3. **File-based review artifact.** The pipeline writes a structured review package, the
   reviewer edits it, and a resume command reads it back and derives `ReviewerDecision`
   records. Matches roadmap Stage 2's "CLI-based or simple structured files," and is
   diffable, which is useful for the demo.

### Also decide

- The **workflow-state schema**: turn `data-model.md` section 31's illustrative structure
  into a real one, honouring its state-design rule that full source documents, prompt
  transcripts, and every generated object stay out of the state payload.
- The meaning of **`WorkflowRun.checkpoint_reference`**.
- **Resumption identity**: how a paused assessment is found and resumed after the process
  exits.
- The **review-package contents** for each checkpoint. `agent-design.md` sections 9 and 18
  enumerate the reviewer actions; the package must show enough for each. This closes
  DEC-005's open question.

### Decision criteria

- Can an evaluation run supply pre-recorded reviewer decisions without disabling the
  checkpoint? See DX-01 — answering non-interactively and bypassing are different things.
- Does state survive process exit?
- Does the same machinery serve both checkpoints, with only the package contents differing?
