## Context

No model provider and no model have been selected. `anthropic`, `openai`, `langchain`,
`langchain-anthropic`, `langchain-openai`, and `instructor` are declared in
`pyproject.toml` and imported nowhere; `README.md` and `CLAUDE.md` both state that their
presence is not a choice.

`docs/architecture/current-architecture.md` section 9 requires a model abstraction layer
rather than direct provider calls scattered through the codebase, supporting structured
output, timeouts, retry limits, token limits, cost metadata, and test substitutes.
`AssessmentConfiguration.model_profile` is a required field
(`docs/architecture/data-model.md` section 6) whose only example value is
`primary-development` and which points at no registry.

This decision blocks every agent. It also has to be made carefully: any plausible default
for `model_profile` implies a provider has been chosen, which would answer this question
by accident.

## Scope

Decide three things together, because they interact.

### Provider and model

`agent-design.md` section 28 says the MVP should begin with one primary capable model.
Criteria: structured-output reliability under a strict schema, since every agent returns
validated objects; context-window headroom for the ForgeFlow corpus (seven Markdown
documents plus structured YAML); cost and latency at benchmark scale, since the evaluation
plan re-runs 8 to 12 scenarios per prompt change; data-handling terms, since
`current-architecture.md` section 12 names the model-provider boundary explicitly.

### The abstraction seam

A protocol taking a rendered prompt, a target Pydantic model, and generation settings, and
returning either a validated object or a structured failure **carrying the raw output** —
`data-model.md` section 33 requires invalid output be preserved for debugging. The response
must carry token counts and estimated cost so `ExecutionRecord` can be populated and
`maximum_model_calls` and `maximum_cost` can be enforced.

### Structured-output strategy

Options: `instructor`, native provider structured output or tool-schema forcing,
LangChain's `with_structured_output` (only if DX-06 accepts LangGraph), or a hand-rolled
schema-in-prompt plus `model_validate_json` with an application-owned repair loop.

The decisive criterion is retry ownership. `agent-design.md` section 26 and section 27
give the orchestrator the retry budget. A library that retries invisibly breaks the
`ExecutionRecord` retry count and the cost ceiling. The decision must state which component
owns the budget and that the client makes exactly one attempt per call.

## Acceptance criteria

- [ ] An entry is added to `docs/architecture/decision-log.md` naming the provider, the
      model, the seam's methods and its success and failure return types, and the
      structured-output strategy.
- [ ] The entry defines `model_profile` — at minimum model id, temperature, max tokens,
      timeout — or defers the registry explicitly.
- [ ] The entry states which component owns the retry budget and how a validation failure
      reaches `ExecutionRecord`.
- [ ] The entry specifies the test substitutes: a deterministic fake, and whether recorded
      responses are committed.
- [ ] The entry states that every unit test runs with no API key and makes no network call.
- [ ] The entry states that DEC-007 is not implied by this choice.
- [ ] Unselected provider SDKs are removed from `pyproject.toml`, with `uv.lock`
      regenerated, or the entry records why they are retained.
- [ ] `README.md`'s "Model provider and model — Not chosen" row is updated.
- [ ] `.env.example` and `trace_ai.config.Settings` carry only the keys the decision
      requires, and the drift test still passes.
- [ ] `current-architecture.md` open questions 2 and 3 are marked resolved.

## Out of scope

- The orchestration framework, which is DX-06.
- Prompt content. The prompt registry is a separate M2 issue.
- Multi-model or per-agent model selection; `agent-design.md` section 28 says to begin
  with one.
- External tracing, decided separately.
